# Agentic IDE — 6-Month Team Build Plan

**Team:** Rehaan (Frontend / UI / Auth) + Akshat (Backend — Instructions Agent, DB) + Daivik (Backend — Day-Review Agent, Git checkpointing)

---

## STACK

| Layer | Choice | Owner |
|---|---|---|
| Shell | Tauri | Rehaan |
| Editor | Monaco Editor | Rehaan |
| Frontend | React + Vite + TypeScript | Rehaan |
| Styling | Tailwind + shadcn/ui | Rehaan |
| Native layer (Tauri commands) | Rust | Rehaan |
| Git checkpointing | `git2-rs` / system git via Rust | Rehaan (joint design with Daivik) |
| Auth (login/signup UI, session/token handling) | PocketBase Auth SDK, consumed on frontend | Rehaan |
| DB (schema, hosting, the PocketBase instance itself) | PocketBase (single Go binary, SQLite-backed) | Akshat / Daivik |
| Instructions agent (IDEA.md → instructions.md) | Python + FastAPI | Akshat |
| Day-review agent (diff → notes/mistakes/solutions) | Python + FastAPI | Daivik |
| Structured LLM output | `instructor` (Python) or provider-native structured output | Akshat / Daivik |
| API contract | OpenAPI spec (FastAPI auto-generates it) | Shared |

## DAY 0 — Setup Day (all three, same day)

**Rehaan:**
1. Install: Node.js LTS, pnpm, Rust (`rustup`), Tauri CLI, VS Code, Git.
2. Create the GitHub repo (`agentic-ide`), add Akshat and Daivik as collaborators.
3. Set a **branch protection ruleset** on `main`: require PR review, no direct pushes.
4. Push initial skeleton: root `README.md`, `.gitignore` (Node + Rust + Python + PocketBase data), `docs/IDEA.md` stub.
5. Scaffold the Tauri app (`npm create tauri-app@latest`) in `apps/desktop`, React + TypeScript template. Confirm `npm run tauri dev` opens a blank window.
6. Create your branch (`rehaan/desktop-skeleton`), push, open first PR.

**Akshat:**
1. Install Python 3.11+, `uv` or `pip` + `venv`, Git.
2. Download the **PocketBase** binary, run it locally (`./pocketbase serve`), confirm the admin UI loads at `localhost:8090/_/`.
3. Create the initial PocketBase collections: `users` (extend the built-in auth collection), `projects`, `days`, `violations`.
4. Share the local setup steps + schema with the team (a short `pocketbase/README.md`) so everyone can spin up the same DB locally.
5. Scaffold `services/instructions-agent` — FastAPI app with one placeholder route (`/health`). Confirm `uvicorn app.main:app --reload` runs.
6. Create your branch (`akshat/pocketbase-and-instructions-skeleton`), push, open PR.

**Daivik:**
1. Install same Python tooling as Akshat.
2. Scaffold `services/review-agent` — FastAPI app, one placeholder route (`/health`).
3. Write a short decision note in `docs/ARCHITECTURE.md`: `git2-rs` vs. shelling out to system git from Rust, and what a "day checkpoint" actually means (commit boundary, diff scope, reset behavior).
4. Create your branch (`daivik/review-agent-skeleton`), push, open PR.

**All three, end of Day 0:**
- Sync for 15 minutes. Confirm everyone's skeleton runs, including PocketBase running locally for all three.
- Merge all PRs into `main`.
- Agree on `docs/openapi.yaml` v0 — rough shape of the instructions-generation and day-review endpoints, just enough to unblock parallel work tomorrow.

## WEEK 1 — Days 1–5

**Day 1**
- Rehaan: Embed Monaco Editor in the Tauri window. Verify `editor.onDidPaste()` fires and logs to console.
- Akshat: Write the first version of the IDEA.md → instructions.md prompt in the instructions-agent. Single LLM call, no structure yet.
- Daivik: Build the `/review` endpoint in review-agent as a stub — accepts a diff, returns a hardcoded mock `{notes, mistakes, solutions, violation: false}`.

**Day 2**
- Rehaan: Build the file tree component — read a local folder via Tauri's fs API, render it in the sidebar.
- Akshat: Test the instructions.md agent against 2–3 different sample IDEA.md files. Note inconsistencies. Also finalize the `days` and `violations` PocketBase collection schemas.
- Daivik: Sketch the real day-reviewer prompt (not just the endpoint) — what context it needs (the diff, the expected day's tasks from instructions.md) to give useful notes.

**Day 3**
- Rehaan: Add tabbed editing (multiple open files) using Monaco's model system.
- Akshat: Add structure to the instructions.md output — force the agent to return day-by-day JSON via `instructor` or FastAPI's response_model.
- Daivik: Start the Rust git command (`src-tauri/src/commands/git.rs`) — implement `init_project_repo` and `commit_checkpoint`. Pair with Rehaan for an hour since this lives inside the Tauri app.

**Day 4**
- Rehaan: Wire the sidebar to display Akshat's structured instructions.md JSON (mock the API call with a local JSON file for now).
- Akshat: Add error handling + retries to the instructions agent; write 5 more test IDEA.md samples covering edge cases.
- Daivik: Implement `get_diff_since_last_checkpoint` in the Rust git command.

**Day 5 — Integration checkpoint**
- All three: connect the real instructions-agent to the desktop app for the instructions.md flow only. Write a real IDEA.md, generate a real instructions.md, see it render in the app. Don't move on until this end-to-end slice works.

**End of Week 2 checkpoint:** full loop should work — write IDEA.md → get instructions.md → do fake "Day 1" work → submit → get real review notes back → trigger a paste → see the day reset and PocketBase flag the violation.

## MONTH 2 — Core Loop Stabilization

- Fix everything flagged in the Month 1 dogfood session.
- Add support for multiple concurrent projects per user.
- Add loading/error states everywhere API calls happen (Rehaan).
- Improve day-reviewer mistake-detection accuracy against intentionally buggy sample submissions (Akshat + Daivik).
- Start a lightweight CI workflow: lint + build check on every PR, for both the Rust/TS side and the two Python services.

---

## MONTH 3 — Feature Completion

- Full profile page: badges, completion certificates, violation history with dates.
- Copy-paste violation hardening: cover right-click-menu paste and keyboard-shortcut paste, test across Windows/Mac/Linux since Tauri behavior can differ per OS.
- Settings screen (theme, font size, keybindings).
- Onboarding flow: first-time user walked through writing their first IDEA.md.

---

## MONTH 4 — Testing & Hardening

- Full bug bash: each of you tests the other two's areas as an outsider.
- Security pass: can a student bypass the paste block (fast typing, OS-level automation)? Decide in-scope defenses vs. accepted known limitations.
- Performance pass: large files in Monaco, large git histories, agent response latency, PocketBase under concurrent load.
- Write real setup documentation — good enough a stranger could clone and run the whole project, including standing up PocketBase and both Python services.

---

## MONTH 5 — Beta Testing

- Get 5–10 real external users through one full project.
- Collect structured feedback: unclear instructions.md moments, unhelpful/wrong agent reviews, confusing UI moments.
- Triage into "must-fix before launch" vs. "later."
- Fix the must-fix list.

---

## MONTH 6 — Launch Prep

- Polish based on beta feedback.
- Record a demo video: idea → instructions → coding → review → completion.
- Prepare distribution plan (GitHub release + README, or a simple landing page).
- Final full end-to-end test across all three machines before calling it done.
